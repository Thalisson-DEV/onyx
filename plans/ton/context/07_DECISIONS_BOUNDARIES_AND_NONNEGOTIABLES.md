# TON — DECISÕES, FRONTEIRAS E NÃO NEGOCIÁVEIS

## 1. Onyx x TON

Decisão atual:

```text
Onyx = infraestrutura
TON = produto
```

A camada cliente pode ser totalmente própria.

---

# 2. TON x especialistas

TON:
principal coordenador/user-facing.

Especialistas:
papéis de execução internos.

Canonical:
CFO, COO, FROTA, CONTRATOS, COMPLIANCE, PROCUREMENT, RH, AUDITOR, CEO.

Não presumir nove Personas independentes.

---

# 3. IA x determinismo

Determinístico:
- parsing;
- validação;
- regra financeira;
- reconciliation;
- readiness;
- DRE calculation;
- lineage.

IA:
- interpretação;
- síntese;
- explicação;
- priorização assistida;
- linguagem;
- interface.

Nunca inverter isso.

---

# 4. Reviewed vs truth

O arquivo “ok” revisto pela Controladoria:
é calibração/evidência histórica.

Não é automaticamente “verdade”.

Uma divergência entre TON e revisão humana precisa de:
- explicação;
- cross-source;
- contexto humano;
- ou classificação de incerteza.

---

# 5. Imutabilidade

Preservar:
- source snapshots;
- review runs;
- findings/evidence;
- mapping revisions;
- DRE versions;
- reports.

Não editar histórico silenciosamente.

---

# 6. Human decision boundary

Humano decide:
- mappings;
- authority;
- ambiguous reconciliation;
- legal interpretation;
- corrections;
- external communication;
- critical closure.

TON pode sugerir e explicar.

---

# 7. Não escrever em sistemas externos

Até agora:
TON é read/analysis/recommendation.

Não escrever em NG/Keevo.

Não modificar arquivo original.

Não “corrigir” ERP silenciosamente.

---

# 8. Missing data

A ausência de fonte é um estado de produto.

Exemplo:
`Integração direta NG/Keevo — aguardando acesso`

Não:
`NG conectado`
sem prova.

---

# 9. Budget

Nunca:
- annual/12;
- filename date;
- guess calendar period;
- infer budget period from amount.

---

# 10. Amount basis

Realizado pode exigir decisão:
MOVEMENT vs FINAL.

Não escolher porque “parece correto”.

---

# 11. Account/DRE mapping

Não:
- fuzzy matching;
- semantic similarity;
- LLM auto-classification;
- hardcoded client mappings.

Candidate can be shown only when deterministic evidence supports it.

---

# 12. Privacy / source artifacts

Real Vale Norte files:
- não entram no Git;
- não viram fixture;
- não vão para migrations;
- não são despejados em logs;
- não são copiados para docs.

---

# 13. Synthetic data

Permitido em dev/demo.

Obrigatório:
- aviso claro;
- nunca parecer dado real;
- valores não serem usados para claims comerciais reais.

---

# 14. Prompt Mestre

O Prompt Mestre é a origem da intenção de negócio.

Mas registration/cobertura de uma capability não significa que sua execução está implementada.

Não dizer:
“regra existe” = “regra operacional”.

---

# 15. Admin

Normal client:
não deve navegar pelo admin para usar TON.

Admin:
pode acessar configurações técnicas.

---

# 16. Browser truth

Visual QA é parte do aceite.

Build passing != UI pronta.

---

# 17. Commit discipline

Projeto trabalha em `main` local.

Não:
- push;
- stash;
- reset de trabalho alheio;
- rebase;
- branch de conveniência;

sem instrução explícita.
